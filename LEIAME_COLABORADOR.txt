2) O QUE VOCE PRECISA CRIAR (nunca vai no zip nem no Git)
---------------------------------------------------------
1. .env: copie .env.example para .env e preencha.
   - SMARTPARK_MODE=firestore
   - GOOGLE_APPLICATION_CREDENTIALS: caminho de uma chave JSON de conta de servico, guardada FORA
     da pasta do projeto (ex.: ~/.smartpark/firebase-key.json, permissao 600).
   - FIREBASE_PROJECT_ID e FIREBASE_WEB_API_KEY (Firebase Console > Configuracoes do projeto).
   - DEVICE_ID=esp32-centro-01 e DEVICE_SHARED_SECRET (gere: python -c "import secrets; print(secrets.token_urlsafe(32))").
   - APP_BASE_URL: URL HTTPS do tunel, sem barra no final.
2. Chave do Firebase: peca acesso ao projeto ao dono OU receba a chave por canal seguro.
   Nao envie por e-mail/zip/Git. Em caso de duvida, gere uma chave nova.
3. Mercado Pago: aplicacao de TESTE no painel de desenvolvedores (token e segredo de webhook de teste).
4. Telegram: bot novo no BotFather (token novo).
5. Wokwi: copie firmware/config.example.h para uma aba config.h e preencha (URL do tunel,
   DEVICE_ID, DEVICE_SECRET igual ao DEVICE_SHARED_SECRET, certificado RAIZ do dominio do tunel).


3) COMO RODAR
-------------
    python3 -m venv .venv
    source .venv/bin/activate            (Windows: .venv\Scripts\activate)
    pip install -r backend/requirements.txt
    python -m scripts.check_firebase     (deve responder OK)
    python scripts/seed.py               (uma vez, com o servidor parado)
    python app.py                        (abre em http://127.0.0.1:5000)
    python3 -m unittest discover -s tests -v     (testes)
Tunel (para webhooks e Wokwi): cloudflared tunnel --url http://127.0.0.1:5000
A URL do tunel gratuito MUDA a cada reinicio: atualize APP_BASE_URL e API_BASE e reinicie o backend.
Mudou o .env? Reinicie o backend.
Worker de notificacoes (Telegram): python -m scripts.notifications (outro terminal, mesmo ambiente).
Permissao de operador: custom claim "operator" (veja docs/GUIA_EQUIPE.md); sair e entrar de novo.

C. Wokwi: FALHA_REDE
   - Sintoma: "[API] ... -> -1 | connection refused | TLS: ERROR - Generic error". E falha ao ABRIR a

D. Ensaio integrado (T07 a T11) com uma reserva paga e confirmada; preencher o "Registro de ensaio

E. Entregas formais: link do projeto Wokwi (sem segredos), prints do webhook/status do pagamento sem

5) REGRAS QUE NAO PODEM SER QUEBRADAS (roteiro)
-----------------------------------------------
- Reserva so fica CONFIRMED depois que o backend verificar o pagamento aprovado no provedor.
  Retorno do navegador a pagina de sucesso nao comprova pagamento.
- Preco sempre calculado no servidor a partir do banco; o navegador nao e fonte do valor.
- ESP32 nao guarda token do Mercado Pago, do Telegram nem credencial do Firebase.
- Acesso decidido pelo backend; sem validacao a cancela fica fechada (nega por padrao).
- Eventos de entrada/saida e webhooks sao idempotentes (event_id; sem cobranca ou ticket duplicado).
- Certificado HTTPS verificado no ESP32 (setCACert), sem setInsecure.


6) SEGURANCA
------------
- Nunca versione .env, chaves JSON nem config.h (ja estao no .gitignore). Confira com: git ls-files
- A chave do Firebase e o token do bot que circularam antes em arquivos do projeto precisam estar
  REVOGADOS (Google Cloud > IAM > Contas de servico > Chaves; BotFather > /revoke). Confirme com o dono.
- Troque DEVICE_SHARED_SECRET e o segredo no config.h se o projeto do Wokwi for exibido ou compartilhado.
